# CCISS historical raster comparison

This snapshot supports PGMaps' historical lodgepole pine (`Pl`), edatope `C4`
comparison and reference BGC numeric lookup. The original downloads were obtained
from the public CCISS Spatial page's **Download Province** control on 2026-09-27.
Original downloaded TIFFs are retained unmodified in `output/`; the COG is a
lossless prepared copy. See `output/provenance.json` for checksums and selections.

The suitability download is `FeasibilityRaw_1961_1990_C4_Pl.tif` in Shiny's
download handler. The public mapped tile product is named
`NewFeas_1961_1990_ref_C4_Pl`, and its values differ in some locations. This
snapshot does not claim those products are equivalent or provide the separate
site-series model inputs used by CCISS reports.

The generic converter is `../../lib/categorical_raster.py`:

```sh
uv run --with rasterio==1.5.1 python datascrapers/lib/categorical_raster.py \
  --input datascrapers/bc/cciss/output/historical-download-1961-1990-C4-Pl.tif \
  --output /tmp/cciss-polygons-new
```

After validation, the generated directory belongs at
`output/historical-Pl-C4-polygons`. It contains 308 native grid blocks,
79,887 polygons, and 6,900,717 compressed tile bytes for this snapshot. All
35,646,021 cells, including 11,028,673 valid cells, pass the class/NoData round trip.
Class counts: 10 = 4,283,171; 20 = 5,334,373; 30 = 1,411,129.

PGMaps copies this output to ignored `public/data/cciss` via
`npm run data:sync-from-bcdatamapper`. Commit and push the scraper snapshot first
before updating the parent submodule pointer for deployment. Never add the
generated app copy to the parent repository.

## Numeric polygon display overviews

`output/historical-Pl-C4-overviews/manifest.json` is the portable zoom pyramid for
the numeric vector view. It is built from the exact original
`historical-download-1961-1990-C4-Pl.tif`, checksum
`b104172c84412c9046e63adb391d0c62d40523914ca4499f583343ad0649f65e`, and references
the existing `historical-Pl-C4-polygons/manifest.json` unchanged at full detail.
No traced image classes are involved.

| Zoom | Display grid | Blocks in entire layer | Compressed geometry bytes |
| --- | --- | ---: | ---: |
| Below 6 | 1:8 nearest-cell-centre overview | 10 | 530,911 |
| 6–7 | 1:4 overview | 27 | 1,391,131 |
| 7–8 | 1:2 overview | 87 | 3,435,502 |
| 8+ | Original full-detail grid | 308 | 6,900,717 |

The renderer requests intersecting blocks rather than the entire layer. Its
existing zoom deadband and cache apply to this pyramid too. The small overview
reduces province-scale requests while the original grid remains available on
zoom-in. Exact numeric point results continue to read the original TIFF at every
zoom; an overview pick is explicitly generalized and must not be used for area
calculations or treated as new ecological resolution. Small patches can vanish
and boundaries can shift within the coarser grid.

Prepare a fresh candidate (the output directory must not already exist):

```sh
uv run --with rasterio==1.5.1 python \
  datascrapers/bc/cciss/prepare-numeric-overviews.py \
  --output datascrapers/bc/cciss/output/historical-Pl-C4-overviews-new \
  --verify-determinism
```

The CCISS wrapper uses the generic `categorical_overviews.py` pipeline. It checks
the original source checksum, independently compares each overview's sampled
mask and numeric values, preserves source extent/CRS/band type/NoData and checks
class counts against polygon manifests. The generic converter checks every
overview cell and its published polygon geometry on rasterization. A sibling
repeat build verifies every generated byte is deterministic; full-detail data
is reused, not rebuilt. `validation.json` records the source and level checks.
The accepted published snapshot is `historical-Pl-C4-overviews`; candidate
directories are not additional app datasets.

```sh
uv run --with rasterio==1.5.1 python datascrapers/lib/test_categorical_overviews.py
uv run --with rasterio==1.5.1 python datascrapers/lib/test_categorical_raster.py
```

## Public tile tracing pilot (2026-09-27)

`trace-public-tiles.py` reconstructs **display classes**, not measured CCISS
values. It archives a fixed 3×3 zoom-12 tile mosaic (x 628–630, y 1310–1312)
near Fraser Lake, uses the Shiny legend's four RGB colours, marks ambiguous
pixels as 99, and preserves transparent pixels as NoData. Euclidean sRGB
thresholds (distance <=60, runner-up margin >=20, alpha >=250) are heuristics,
not calibrated confidence. The generic classifier is `../../lib/palette_classes.py`.

```sh
uv run --with rasterio==1.5.1 python datascrapers/bc/cciss/trace-public-tiles.py \
  --longitude=-124.666920 --latitude=54.209275 \
  --archive datascrapers/bc/cciss/sources/public-tile-trace \
  --output /tmp/cciss-public-trace-new
```

The accepted snapshot is in `output/public-tile-trace`: provenance, explicitly
named `inferred-display-classes.tif`, and verified polygons. The nine original
WebPs live in `sources/public-tile-trace`. Source URLs and checksums are recorded.
All 589,824 pixels round-trip through the polygons unchanged. There are 494,769
inferred High pixels, 92,592 Moderate and 2,463 uncertain (0.4176%). The latter
render purple. 102 polygons occupy 94,908 compressed bytes. No boundary smoothing
is applied; shared raster edges remain shared. All 12 output files were byte
identical on a repeat build from the archived source images. These checks prove
fidelity to the inferred raster, not to an unavailable numeric source.

### Matching source search

The live TileJSON lists `/sapho/kdaust/FFEC/suitability_rasters/NewFeas_1961_1990_ref_C4_Pl.tif`,
a server filesystem path, not a public download URL. The tile-server index links
only to this layer's TileJSON and preview. A direct HTTPS request to
`/data/NewFeas_1961_1990_ref_C4_Pl.tif` returned 404. The official Environmental
Suitability Ratings catalogue (1810fdca-8762-4d6a-8886-4e8cefbdb640) lists a ratings
CSV and documents, not this raster. The Biogeoclimatic Projections catalogue
links back to the Shiny app. Its public source download handler selects
`FeasibilityRaw_1961_1990_C4_Pl.tif`, already in this snapshot. No matching public
GeoTIFF download was found; the file has not been acquired or converted.

To complete that path, request **the original single-band class raster used to
build `NewFeas_1961_1990_ref_C4_Pl.mbtiles`**, together with the CRS, NoData, class
legend and version/date. Inspect the returned TIFF's bands: the filename alone
does not establish that it contains numeric classes rather than rendered RGB.
Do not relabel the traced TIFF or the existing `FeasibilityRaw` download as this
missing source. No contact request has been sent.

## Grid-based reconstruction (default Tile trace view)

Run the same command with `--grid` and a fresh output path. This requires archived
`tilejson.json` alongside the WebPs. `grid_class_reconstruction.py` accepts the
assumed geographic grid origin and step separately from the display classes.
This pilot uses the layer bounds' west/north origin (-139.000139, 60.000139) and
an assumed 10-arc-second (1/360 degree) step, supported by the repeated boundaries
in the captured image. It is a geographic grid, not a square-metre grid.

Vote using classified pixel centres in each cell's central 60% width/height.
Require at least four classified pixels, >=80% classified coverage and >=80%
agreement for a winner. Conflicting/sparse cells remain uncertain; fully missing
interiors stay NoData. Publish only complete captured cells, with no extrapolation
at the edge of the nine-tile mosaic. Reject a build if fewer than 99.5% of eligible
classified image pixels agree with the inferred cell raster. This gate includes
pixels outside the voting interiors, but it is not independent source-data truth.

`output/public-grid-trace` has 5,170 cells (4,337 inferred High, 833 Moderate).
Every cell had unanimous classified interior votes with at least 32 pixels;
no cell is uncertain in this sample. All 575,925 eligible classified image pixels
within its extent agree on rasterization back to the image grid. Compression-
ambiguous image pixels and cropped partial border cells are excluded from that
comparison. The 5,170-cell native/published geometry round trip passes too.

Adjacent equal classes merge into 3 polygons / 997 gzip bytes. The older pixel
trace remains available via **Image pixels**; **Grid cells** is the default.
Grid unit tests cover edge noise, class conflicts, sparse evidence, NoData and
partial-cell clipping. This remains inferred display data; using the grid does
not recover model-member values or validate per-site calculations.

## Legacy browser analysis package

`prepare-legacy-analysis.py --source /path/to/CCISS_ShinyApp-main` prepares
`output/legacy-analysis`: 32 unchanged numeric BGC TIFFs, 10 regional gzip JSON
summaries and ecological lookup tables, about 12.9 MB. The complete older source
data are about 489 MB and are not copied wholesale. Source paths/checksums and
licence are retained; no current prediction arrays are claimed.

**Codebook discrepancy:** the bundled levels.bgc.csv does not match the TIFFs.
Conversion requires unique count-signature matches across all 37 BC BGC rasters
and their labelled summary rows. All 324 present codes match uniquely; 315 labels
change. The method and warning are recorded in the manifest. Browser point
results remain provisional pending an authoritative matching codebook. Regional
species ratios use explicitly labelled tables and do not depend on this repair.

The PGMaps implementation and full current-data requirements are documented in
`docs/cciss-client-analysis.md` in the parent repository.

## Current browser pilot handoff

The browser accepts the raw `cciss-current-pilot-v1` SQL export for weighted BGC
probabilities. Species calculations additionally need a self-contained
`cciss-current-analysis-v1` bundle, with a compatible ecological attachment and
an explicit provider assertion that the versions match. The available public
development S1 object still has a different schema; this workflow does not rename
its columns or assume that it belongs to the deployed calculator.

An authorized database owner can run `export-current-pilot.sql` with 1–25 unique,
integer site IDs on their own host. It remains a read-only, repeatable-read query;
it has not been executed against the live CCISS database here. Invalid or duplicate
IDs are reported as an invalid request rather than silently deduplicated. The
owner must confirm database table/column names first.

Validate and package an owner-supplied export:

```sh
python datascrapers/bc/cciss/validate-current-pilot.py /path/to/pilot.json
python datascrapers/bc/cciss/pack-current-pilot.py \
  --pilot /path/to/pilot.json \
  --provenance /path/to/provenance.json \
  --ecology /path/to/ecology.json \
  --output /path/to/current-analysis.json
```

The provenance object requires `datasetVersion`, `source`, and boolean
`versionMatched`. A full 40-character `ccissrCommit` is required when
`versionMatched` is true; it is optional for an unverified probability-only
bundle. `shinyCommit` is optional but must also be a full commit when supplied.
`versionMatched` records the supplier's
assertion; neither packaging nor importing independently certifies it. Keep model,
data and table version descriptions in `datasetVersion` and `source`, together
with an external delivery record if needed. Do not put credentials in these files.

`ecology.json` has the following shape, preserving source rows and values:

```json
{
  "schema": "cciss-ecology-v1",
  "tables": {
    "E1": [],
    "E1_Phase": [],
    "S1": []
  }
}
```

The empty arrays above describe the envelope, not a ready dataset. E1 and S1
must contain rows. E1 uses `BGC`, `SS_NoSpace`, `Edatopic`, and nullable
`SpecialCode`; E1_Phase additionally uses `MainUnit`. S1 uses `BGC`,
`SS_NoSpace`, `Spp`, and integer-valued numeric `Feasible` (1–5), with optional
boolean `OHR`. For example, an R numeric JSON value `1.0` is the same rating as
`1`; strings such as `"1"` are rejected. `OHR: null` is rejected; omit the column
when its meaning is unknown and keep out-of-range filtering unavailable.
Column case and rating semantics are significant. Other supplied tables remain
in the package as provenance, but the current browser calculation does not
produce stocking/CFRG flags from them.

The source prediction contract needs original `bgc` labels in the codebook and
attribution, `bgc_pred` (string or null) in the observed row, and four-digit
`futureperiod` years such as `2021`, `2041`, `2061`, and `2081`. The prepared SQL
casts the year to text. Direct older exports with integer-valued JSON years are
also accepted without changing the year or rewriting the original array.
Periods are not mapped from legacy date ranges, and future dimensions cannot
reuse the reserved `1961` baseline or `1991` observed IDs.
The complete GCM × scenario × period × run index
must remain in source ordinal order, including null prediction members. Novelty
values retain their original encoded scale; they are not proportions. A missing
observed prediction or future member is retained as missing.

The packer preserves all arrays and records, writes deterministic JSON and emits
a SHA-256 receipt. It refuses malformed/ambiguous JSON, conflicting dimensions,
invalid geometry, guessed S1 aliases, input overwrites, and pilot packages larger
than the browser's 25 MB import budget. Omitting `--ecology` produces a versioned
probability-only bundle. This structural gate establishes neither ecological
validity nor equivalence to real Shiny results.

### Synthetic regression fixture

`fixtures/synthetic-current-analysis.json` is a complete, deliberately invented
browser-import fixture. Its sites are squares near longitude 0 and 2, and every
BGC, model, scenario, species and run uses an artificial `TEST` label. It is
marked synthetic in both raw input and provenance and must never be presented
as a real assessment. The attached source-compatible rows let tests exercise
the calculation path; they do not validate the published ecological tables.

Two models × two scenarios × four periods × two runs give 32 ordered members.
The mapped and observed BGC is TESTalpha. All 2021 members predict TESTalpha;
later model-1 members predict TESTbeta and model-2 members predict TESTgamma.
For equal model/scenario weights, later BGC probabilities are 0.5/0.5. The
encoded novelty values are 10 for model 1 and 70 for model 2, so a 5-sigma
cutoff makes the latter half novel. The tables use one regular site series per
BGC and shared C4/D4 edatopes; no special/phase parity is implied by this fixture.

Rebuild the exact fixture bytes and run the dependency-free handoff tests:

```sh
python datascrapers/bc/cciss/pack-current-pilot.py \
  --pilot datascrapers/bc/cciss/fixtures/synthetic-current-pilot.json \
  --provenance datascrapers/bc/cciss/fixtures/synthetic-current-provenance.json \
  --ecology datascrapers/bc/cciss/fixtures/synthetic-current-ecology.json \
  --output /tmp/cciss-synthetic-current-analysis.json
cmp /tmp/cciss-synthetic-current-analysis.json \
  datascrapers/bc/cciss/fixtures/synthetic-current-analysis.json
python datascrapers/bc/cciss/test-current-pilot.py
```

The remaining external input is an authentic, version-matched pilot with its
deployed tables, model settings, `dbPointInfo` results and expected CSV/RDS output
for the same sites. No public matching prediction/grid export was found in the
latest inspected repositories; `ccissr` development still resolves to
`a6ab8ee3a714ebf4a3f41e16f04d9f58404de7ce`, and neither `ccissr` nor
`CCISS_ShinyApp` publishes release assets at this check. Broader coverage needs
a versioned spatially partitioned export after real-site comparison succeeds.
