# BC economic regions

```sh
npm run economic-regions:sync
npm run economic-regions:validate
```

The sync downloads and caches the eight **2021 Statistics Canada economic
regions** covering all of BC. Add `-- --refresh` to refresh the source caches;
ordinary runs rebuild reproducibly without network access when caches exist.
The geometry source is the [2021 digital boundary service, layer 2](https://geo.statcan.gc.ca/geo_wa/rest/services/2021/Digital_boundary_files/MapServer/2).
These are statistical analysis regions, not governments or NDIT service regions.

The [official SGC economic-region classification](https://www23.statcan.gc.ca/imdb/p3VD.pl?CLV=2&CPV=59&CST=01012021&CVD=1368932&Function=getVD&MLV=5&TVD=1368923)
is followed from province to economic region, census division and census
subdivision. Every relationship comes from the classification, not a spatial
join, name matching or code-prefix guessing. All 29 CDs and 751 CSDs are
included, with source links, names and types.

Example: **BC 59 → Cariboo 5950 → Fraser-Fort George 5953 → Prince George
5953023**. CDs include regional districts and statistical equivalents such as
Stikine. CSDs include municipalities, electoral areas, reserves and other
municipal equivalents. Do not call every CSD a municipality or infer governance
relationships from this statistical hierarchy. Keep joins on the same geography
vintage; the existing national current-CSD layer is newer than this 2021 crosswalk.

NDIT's dashboard combines North Coast and Nechako for some indicators. The
hierarchy JSON records this grouping without changing the eight canonical
polygons. NDIT's four service regions cut across economic regions: for example,
Central Coast CD is in the Vancouver Island and Coast economic region. Never
use a single universal "Northern BC" polygon for every dashboard indicator.

## Source and deployment ownership

- Full source geometry and official membership cache: `source/StatCanEconomicRegions/*.gz`.
- Deployable geometry: `output/StatCan/bc_economic_regions_2021.geojson.gz`.
- Manifest, full membership hierarchy and validation report: adjacent JSON files.
- PGMaps assembles these at `/data/boundaries/StatCan/` through its existing
  boundary sync rule. No generated public copies are committed to PGMaps.
- Shared boundary selector: **Census boundaries → BC Economic Region (2021)**;
  stable selection IDs are `census:economicRegion:<ERUID>`.

## Geometry and verification

Source native CRS is EPSG:3347; the service returns complete geometry in WGS84.
All eight adjacent polygons are processed together by the shared, pinned
Mapshaper 0.6.113 pipeline in BC Albers (EPSG:3005), using topology-preserving
Ramer-Douglas-Peucker at **50 metres** with cleaning and shape preservation.
This tolerance is for province/regional display, not parcel-scale analysis.
Output is WGS84 at eight decimal places, deterministically gzip-compressed.
Digital boundaries include water; `sourceLandAreaKm2` is retained separately
from polygon area.

The validator checks all 28 feature pairs, validity, exact shared edges, source
area changes in BC Albers, IDs, counts, hashes and full membership consistency.
The initial build has 12 adjoining pairs, 6,335 shared segments, zero overlaps,
and a maximum area change of 0.00664%. Payload sizes are about 1.33 MB raw,
413 kB optimized and 155 kB gzip. The numeric report is regenerated by the
validator; inspect multi-region junctions visually when changing the pipeline.
